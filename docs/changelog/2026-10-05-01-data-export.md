# Data Export: a copy of the workspace's records

The sidebar's *Data Backup & Export* link went nowhere. It now opens **Data Export**
(`/system/data-export`): an HR Manager picks the kinds of record to take, CSV or JSON,
with or without the uploaded files, and gets one ZIP of the company's records. It is
for keeping, for an auditor, or for moving to another system, including before the
company stops using SYNAPSE, as the Privacy Policy and Terms promise. The database is
backed up by Supabase, so this exports and does not back up. See
[ADR 0066](../decisions/0066-data-export-a-copy-of-the-workspace-not-a-backup.md) and the
[module doc](../modules/data-export.md).

> **Security fix, app-wide.** Building this module's isolation tests showed that route
> bindings (`{employee}`, any hashid) were resolved before the tenant was bound. Any
> organisation's record could be reached by its URL, on the web and the mobile API. The
> tenant middleware now runs ahead of route binding. See *Tenancy* below.

## Highlights

- **Everything you can see, nothing more.** 22 datasets in the sidebar's order, each
  guarded by the view permission of its screen, each showing its record count. A test
  fails if a table holding an organisation's records is neither exported nor left out
  on purpose.
- **A faithful copy.** Raw rows, every column, archived records too, ids kept so the
  tables link up. A `manifest.json` for software and a `README.txt` for people.
- **Secrets stay behind.** No password hashes, two-factor secrets, verification or
  invitation codes, join code or app tokens, and no one's private assistant chats.
- **Only the person who asked can download it,** for 7 days, and only while they still
  have access to everything in it. Requests, downloads and deletes are in the activity
  log.
- **Private storage.** Archives go to a private Supabase bucket
  (`SUPABASE_EXPORTS_BUCKET`), never the public upload bucket, and every download
  streams through the app after its checks.
- **Safe in Excel.** UTF-8 with a byte-order mark, and formula-looking text (applicants
  type their own details) is defused with a leading apostrophe.

## Backend

- Migration `2026_10_05_000000_create_data_exports_table`: `data_exports`, grown from
  the draft ERD's `BACKUP`. It publishes `data-export.view` and `data-export.create`
  (new *Data Export* group, 82 permissions in all) and grants both to every HR Manager
  role.
- `Models\DataExport`: statuses, `RETENTION_DAYS` (7), `STALE_AFTER_MINUTES` (60), the
  in-progress, stale and past-retention scopes.
- `Support\DataExport\DataExportCatalogue`: datasets, permissions, explicit
  per-table confinement (`tenant`, `self`, `members`, `roles`, `work_locations`,
  `global`), excluded columns and tables, and file columns.
- `Support\DataExport\ArchiveBuilder`: streams each table (`lazyById`) to CSV or JSON,
  copies uploads from the `public` disk, and writes the manifest and the README.
  Driver-aware boolean and JSON detection.
- `Support\DataExport\DataExports`: request (one at a time per workspace, under a
  lock), build (claims the export first, reads one consistent snapshot on Postgres,
  removes an archive stored for a row that failed to save), download, delete, prune
  (expires, fails and notifies stale builds, sweeps killed builds' working files), and
  the download and delete rules.
- Uploads are copied for at most 420 s of a build, so a build always fits PHP-FPM's
  600 s. Any left are counted as skipped and said so. Copies are stored in the ZIP, not
  deflated. User profile photos come along with the accounts.
- An export stuck past an hour reads as failed at once and blocks nothing. The screen's
  poll no longer recounts every dataset (lazy props).
- `Jobs\BuildDataExport`, dispatched after the response, so no queue worker is needed.
- `Console\Commands\PruneDataExports` (`data-export:prune`), scheduled hourly.
- `DataExportController`, `StoreDataExportRequest` and `DataExportResource` on
  `routes/system.php` (`system.data-export.*`).
- `config/filesystems.php`: the `exports` disk (a private Supabase bucket, or
  `storage/app/private/exports`). `.env.example` documents `SUPABASE_EXPORTS_BUCKET`.
- `SystemGuide` gains a `data-export` entry. The assistant points to the screen and
  does not export.

## Tenancy (applies to every route)

- `bootstrap/app.php`: `EnsureAccountIsActive` and `SetCurrentOrganization` are added
  to the middleware priority ahead of `SubstituteBindings`. Before this, both were only
  appended to the `web` and `api` groups, so they ran after the bindings. Route-model
  binding then saw no tenant, `OrganizationScope` did nothing, and another
  organisation's employee, run or export could be opened, changed or deleted by id or
  hashid. The order is now *authenticate, account check, tenant, bindings* on both
  groups.
- `TenancyTest`: a record of another organisation is not reached by its URL on a
  request that starts with no tenant bound. Feature tests keep the test's tenant bound
  across requests, which is why the existing isolation test passed.
- `EmployeeInvitationTest`: the permission test's user was, by accident, also the
  default member of a second organisation. On a real request that is where they land,
  so the employee is now (correctly) not found. The test now uses a member of one
  workspace, and still checks the 403.
- `AwardTypeTest`: reads its log entries in id order. Without an `ORDER BY`, Postgres
  returned them in heap order and the test failed now and then.

## Notes

- **Production: create a private Supabase bucket and set `SUPABASE_EXPORTS_BUCKET`.**
  Without it, archives live on the container's disk and a redeploy removes them.
- A build runs in the PHP-FPM worker after the response, within the 600 s request limit.
  Very large upload sets may later want the queue worker the image already runs. The
  job is ready for it.
- The Docker image was not rebuilt or run for this change.
- Suite: 1,479 tests, all passing (1,442 before). `AwardsAssistantTest`'s front-runners
  case failed once in an earlier full run and passed alone and in the final run. It
  depends on random factory data, in code this change does not touch, and is worth
  pinning down separately.
- The change was reviewed independently. Its findings were checked against the code
  before being fixed (the tenancy bug above, the poll cost, the FPM time limit, and
  several smaller ones).
- Docs: ADR 0066, `modules/data-export.md`, `database/data-export-tables.md`, the ERD
  (§12, and the draft's `BACKUP` row), `deployment.md`, `modules/product-tour.md`,
  `modules/multi-tenancy.md` (the middleware order) and the index.
