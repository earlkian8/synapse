# QR stations: clock in by scanning a changing code at the site

HR can now put a QR code on a screen at a site — a TV at the entrance, a monitor at the
front desk — that people scan to clock in, with the SYNAPSE app or, where HR allows it,
with any phone's camera and their employee number and PIN. The code changes every few
seconds and stops working soon after the screen closes, and a scan counts only from a
phone inside the site, with a precise location, that hasn't clocked in somebody else that
day — and, if HR asks, only on the office Wi-Fi. Every scan, refused ones included, is listed for HR. See
[ADR 0103](../decisions/0103-qr-stations-a-changing-code-scanned-at-the-site.md).

## Highlights

- **A code that's useless away from the screen.** Signed on the server, good for at most
  two turns (30 s by default), and only if a screen was given it. **Reset codes** ends
  every code at once.
- **With the app, or without it.** Each station is scanned either with the app only (the
  strongest), or with any phone's camera: the camera opens a page where people type
  their employee number and the PIN they use at kiosks, choose their own PIN the first
  time, allow their location, take a photo if asked, and punch.
- **Only on the office Wi-Fi**, when HR turns it on: a scan counts only through the same
  internet connection as the screen, which stops a faked location from home.
- **Cheap to keep on a wall.** The screen asks the server once every two minutes for the
  next few minutes of codes (about 30 small requests an hour, none while hidden) and
  draws them itself.
- **Checks that catch the usual tricks.** A forwarded photo, a faked GPS (Android reports
  it), a scan from the car park, a colleague signed in on your phone: each is turned away
  with a reason the person can act on, and the suspicious ones go to the activity log.
- **A station screen made to be read across a room.** The code on a paper plate with a
  bar that runs out with it, the site's clock, three steps, and the names of the last few
  people clocked in. Full screen, kept awake. It shows *Reconnecting* rather than a dead
  code.
- **A screen account that can do nothing else.** `attendance.qr.display` shows a code and
  nothing more; `attendance.qr.manage` sets stations up and reads the scans.
- **QR as a way to punch.** Policies gain *QR station*. QR-only turns the app's button
  into **Scan to Time In**.

## Backend (`server/`)

- `attendance_qr_stations`, `attendance_qr_scans`; `attendance_punches.attendance_qr_station_id`
  and `device_hash`. Policies that allowed every way to punch now allow `qr`.
- `QrCodes` (signing, windows, three-minute batches and the last window given),
  `QrImage` (a code's module grid, packed), `QrScans` (the scan's checks, browser claims
  and sign-in, the office network, tickets, the punch), `QrStationWorkflow`,
  `QrStationsScreen`; `KioskPins::check()` shared by kiosks and browser scans.
- `scan_mode`, `same_network`, `last_shown_ip` on stations; `client` on scans.
- `/q/{code}` and `qr-scan/identify|pin|punch` for browser scans (no sign-in; a
  device cookie; throttled per address).
- `AttendanceClock` takes `qr` (located, selfie rule) and records station and device.
- Web `/attendance/qr` (+ display, code, toggle, reset); API `attendance/qr/scan` and
  `/punch`; `today` now says how the policy takes punches (`capture`); mobile punches carry
  the install id.
- Data Export gains *QR stations* (no secrets, phone ids or addresses). System guide and
  two Help Center articles.

## Frontend

- `features/qr-stations`: the manager (guards strip, stations, latest scans with a
  refused filter), the station form (how it's scanned, office Wi-Fi), and the
  full-screen display with its batched code loop and `QrMatrix` drawing.
- `features/qr-scan` and `pages/qr-scan.tsx`: the phone's browser scan.
- *QR stations* in Attendance's sections; *QR station* in the policy editor.

## Mobile (`mobile/`)

- `expo-camera` (a new native module: needs an EAS build). The scanner screen (it reads
  both the app link and an any-phone station's web address), the `synapse://qr/…` link,
  a precise location with the simulated flag, a keychain install id, and Clock's scan
  buttons.

## Notes

- Tests: `QrStationsTest` (30) and `QrBrowserScansTest` (16). The browser scan was
  driven end to end in headless Chromium at phone width (number, PIN, location, punch).
  Not checked on a real phone: the app's camera, the system camera's deep link, and
  Android's simulated-location flag need a device build.
- Behind a proxy, *office Wi-Fi only* needs `TrustProxies` set so the server sees real
  client addresses.
