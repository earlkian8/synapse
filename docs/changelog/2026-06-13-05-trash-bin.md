# 2026-06-13 — Trash Bin module

A unified **recycle bin** for archived (soft-deleted) records across the system.
Until now each module kept its own "Archived" filter; the Trash Bin gathers them
into one System screen where you can restore items or delete them permanently.

## Highlights

- **One place for all archived data** — users, employees, departments and leave
  types (every `SoftDeletes` model except the tenant), newest-archived first.
- **Type tabs** with live counts, debounced search, restore + permanent-delete per
  row, **bulk** restore/delete on a selection, and **Empty trash**.
- **RBAC, no bypass** — you only see types you can already view, and restore /
  permanent-delete each require the owning module's own permission, re-checked per
  item. No new permission to seed.
- Placed in the sidebar under **System → Trash Bin** (after Activity Logs), shown
  to anyone who can view at least one archivable type.

## Backend

- `Support/Trash/TrashRegistry` — the trashable-type catalogue binding each type to
  its model and its existing view/restore/force-delete permissions (extend in one
  place).
- `Support/Trash/TrashPresenter` — flattens a heterogeneous trashed model into the
  uniform row shape with the actor's per-item `can_restore` / `can_force_delete`.
- `Queries/TrashIndexQuery` — merges each viewable type's `onlyTrashed()` query
  (reusing its `search` + organisation scopes), sorts by archived-at, hand-builds a
  paginator; `summary()` feeds the type tabs.
- `Http/Resources/TrashItemResource` — pass-through so the listing uses the same
  `{ data, links, meta }` envelope (and shared pagination component) as every
  other module.
- `Http/Controllers/System/TrashController` — `index`, `restore`, `forceDelete`,
  `bulk`, `empty`; per-item authorisation by type; best-effort file cleanup on
  permanent delete so purges don't orphan photos; actions logged under `trash`.
- Routes under `/system/trash/*`.

## Frontend

- `features/trash/` — types, routes, constants, `use-trash-filters`, and components
  `trash-toolbar`, `trash-table`, `trash-row-actions`, `bulk-actions-bar`. Page at
  `pages/system/trash/index.tsx`. Sidebar gains a `permissionAny` (any-of) gate.
- The generic `ConfirmDialog` and pagination are reused from the users feature.

## Tests

- `tests/Feature/Trash/TrashTest.php` — rendering, cross-type listing, type filter,
  single + bulk restore/delete, empty, the guest redirect, and the RBAC guards.

## Notes

- No migration. The bin reads existing soft-deletes, so it works the moment it
  ships. Restart `php artisan serve` to pick up the new routes/controller.
