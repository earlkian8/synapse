A **pipeline** is a hiring process: a named, ordered list of **stages** a candidate moves through — for example _Applied → Screening → Interview → Offer → Hired_. Each job posting runs on one pipeline, so different roles can be hired differently: an office role through interviews and an offer, a warehouse role through a trial shift.

Manage them under **Company Setup** → **Recruitment Pipelines**.

## Creating a pipeline

1. Choose **New pipeline** and give it a **Pipeline name**. **Start from template** fills in the classic six-stage process to adjust.
2. Add the stages, in order. Use the arrows to move a stage up or down.
3. For each stage, choose what it is:
    - **In progress** — a step on the way;
    - **This is the Hired stage** — exactly one per pipeline;
    - **This is a Rejected / lost stage** — at least one per pipeline (you might have _Rejected_ and _Withdrew_).
4. Tick **Default pipeline** if new postings should run on it. There is always exactly one default — making another the default moves it.

Stage names are entirely yours; SYNAPSE only cares which kind each stage is. Rankings and recommendations follow your stages' order, whatever you call them.

## Changing a pipeline

Rename stages, reorder them and add new ones at any time — candidates stay on the stage they were on. A stage that still has candidates on it can't be removed, and a pipeline that a posting still runs on can't be deleted.

## Who can do this

Designing pipelines is its own permission, separate from running hiring day to day. A recruiter can move candidates through a pipeline without being able to change the process itself.
